# Changelog

All notable changes to Bulig are recorded here, newest first. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and releases follow the phase tags in the [Roadmap](ROADMAP.md) (`v0.1` to `v1.x`).

## How to write an entry

- Add every change under **Unreleased** as it happens, not at the end of the phase.
- Put each entry under one of these headings:
  - **Added**, **Changed**, **Removed**, **Fixed**, **Security**: the usual kinds of change.
  - **Errors**: something broke (build, CI, deploy, data). Say what failed, the error message, the cause, and the fix. If it isn't fixed yet, mark it **open**.
  - **Conflicts**: merge conflicts, or the code disagreeing with the Roadmap or Architecture. Say which side won and why.
  - **Big changes**: anything that changes the data contract, a route, the stack, hosting or a phase plan. Link the doc you updated.
- Mention the Jira ticket (`SCRUM-xx`) and the PR or commit when there is one.
- At the end of a phase, tag the release, rename **Unreleased** to the version and date, and start a new empty **Unreleased**. The Roadmap asks for a 3-line summary at the top of each release.

### Fixed

- **Saved places disappeared after closing or reloading the app** (2026-11-05, reported by John). With server accounts the app loaded `GET /me/saved` on start, and any failure (the free server waking up, a weak signal) was treated as "nothing saved": an empty list, no error, no retry. Now: `loadSaved` returns null when it couldn't load; the last list is kept on the phone (`bulig.savedCache.<email>`) and shows at once; the server's answer replaces it; a failed load keeps the phone copy (Saved says so), retries after 5, 15, 45 and 120 s, when the phone comes back online or the app returns to the front, and on Try again; with nothing to show it says it couldn't load instead of "nothing saved". Hearts tapped while a load is on its way are kept on top of its answer. Saved also no longer says "nothing saved" while the place data is the bundled backup (server asleep). The phone copy is removed on sign out and account delete. Tests in `auth/savedSync.test.tsx`.
- **Location was off and the dot jumped** (2026-11-05, John). The app took the phone's first fix, often a Wi-Fi or cell-tower guess hundreds of metres off, and then dropped every fix for 3 s, sometimes the sharper one. Now (`location/fixes.ts`): a much rougher fix within 30 s of a good one is ignored unless it lands outside its own error circle (a real move); in a burst the newest fix is passed on when the 3 s wait ends instead of being dropped; the phone's accuracy is kept (`accuracy` on the location context), and anything over 100 m shows "Approximate, within …" with a hollow grey dot instead of the green live dot.
- **The Map showed nothing after #54** (2026-11-04, reported by John). The kept map's element had `position: absolute; inset: 0`, but MapLibre's stylesheet (loaded later, same specificity) set it back to `position: relative`, so it had no height: 360 × 0 px. Now it is sized with `width/height: 100%`, which holds either way (measured 360 × 576 at 360 × 640). My test had checked only the width.
- **"Directions" wrapped onto two lines** on place cards (Saved, Nearby) at 360px. The two action buttons have 12px side padding instead of 20px and never wrap their label.
- **The 404 page sent signed-out people to the login instead of 911.** Its only link said "Go to Emergency Help" but pointed to `/`, which is Home and needs an account. It now links `/emergency` by name.
- **Home's mini map drifted off you, and the maps' "i" button looked like a watermark** (2026-11-04, John). The mini map now always centres on you (zoom from the nearest places mirrored around your position), follows GPS and re-centres after a resize. Both maps show the required credit as one line of small text instead of the "i" button and pop-up. Rendering is lighter: the style is themed before the map is made (no colour flash), POI icons, house numbers, shields, one-way arrows and airport layers are dropped, and the canvas is capped at 2x pixels.

- **Map tab fell back to the list for the wrong reasons, and blamed the connection** (2026-11-04, reported by John: "sometimes it didn't ask for permission, or it asked but just displayed the list"). Causes found in `MapPage.tsx`: (1) the MapLibre file is renamed on every deploy and was not cached, so a phone on the previous version asked for a file that no longer existed; (2) a failed download was never retried; (3) no WebGL (cheap phones, in-app browsers) was reported as "needs a connection"; (4) if the style or tiles never arrived, the spinner stayed forever. Fixes: the service worker keeps the MapLibre file, the OpenFreeMap style and the last 500 tiles; a failed lazy file reloads the app once (`vite:preloadError`, at most once a minute); each reason has its own message, with Try again; a 20 s timeout. The permission prompt itself is the browser's: Chrome stops asking after a few dismissals, Messenger's browser often never asks, and every preview link is its own site. The Map now says when location is off instead of silently showing no dot.

- **Places added in the admin panel seemed missing from Home** (2026-11-04): Home and Map read the same data, so nothing was lost, but Home only names the 3 places at the top of the list, while Map pins all of them. Without GPS that list is by name across every area, and Home still titled it "Nearest to you". Three fixes in `app/src/data/`:
  - Home now says "First listed" without GPS, as UI-UX.md already asked (Nearby already did).
  - `ApiSource` asks with `cache: 'no-cache'`. The API sends `Cache-Control: max-age=3600`, so the browser kept serving the old list for up to an hour after a panel edit; now each open revalidates (a body-less 304 via the ETag when nothing changed).
  - When the sleeping Render server misses the 4 s timeout, the app still shows the bundled files at once, but `DataProvider` now tries the API again after 20, 45 and 90 s and swaps the live data in without a reload. Before, the bundled sample data stayed until the next reload.
  - One record that breaks the contract is now skipped (with a console warning) instead of throwing away the whole API answer and silently falling back to the bundled samples.
- **Glitches on the first preview** (PR #33, 2026-11-01), found by driving the preview on a phone-sized browser:
  - Every page change showed the old and new page through each other (React `<ViewTransition>` cross-fade). Replaced by a fade-in of the new page only.
  - The location prompt opened on the login screen and behind the splash, and allowing it flipped all of Home from "10 places" (every area) to the nearest town (layout shift 0.05). Now asked only inside the app, with placeholders until the first fix.
  - The splash was timed from the start of the page load, so on a real network it flashed for about 0.3s or not at all. Now timed from when it first shows.
  - Services' line above the cards was one line while loading and two once loaded, so the cards dropped (layout shift 0.024 on the live preview). The loading line now has the same shape ("Finding places near you, nearest first. Pick what you need.").
  - The flaky test "finds the area by itself" (it failed about one run in ten, on `main` too) read the saved area before the effect that writes it had run. It now waits for the write.
  - The splash logo sat in a hard white square (the icon file has a white background), most visible in dark mode. Now a rounded tile like the home-screen icon, from the sharper 512px file.
- **Place details no longer says "Loading…" forever** when data fails to load: it shows "Couldn't load data" with Try again, and a Back button (PR #33, 2026-11-01).
- **A new page opens at its top** (PR #33): moving from a scrolled Home to Services used to open halfway down. Back and Forward return to the exact scroll position, kept by the app (`history.scrollRestoration = 'manual'`), so every browser behaves the same.
- **Lighthouse fixes** (SCRUM-28, 2026-10-30): Emergency's guest note no longer pushes content while the numbers load (layout shift 0.195 → 0.071, Performance 85 → 93); the Call 911 button's accessible name starts with its visible words ("Call 911, National Emergency Hotline", WCAG 2.5.3); Ropi's head no longer squashes in its circle; `public/robots.txt` added (SEO 91 → 100). Scores now (mobile): Login 95 / 100 / 93 / 100, Emergency 93 / 100 / 96 / 100 (Performance / Accessibility / Best Practices / SEO). The remaining Best Practices note is the location request on open, which UI-UX.md asks for.
